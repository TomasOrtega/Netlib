# Interface-bound session admission before conntrack

This note specifies a new finite ingress-attachment milestone; it does not change the earlier campus capture or establish a full campus deployment. The selected contract covers whole IPv4 UDP datagrams on isolated routed Ethernet links, ordinary conntrack in zone zero, and fixed NAT. A trusted controller explicitly associates the current authenticated EAP round and subject with a gateway network namespace and a live input-interface instance. Packet headers do not derive that association.

## Admission point and state effect

The pinned IPv4 priorities are:

| Stage | Priority |
| --- | ---: |
| Raw before defragmentation | -450 |
| Conntrack defragmentation | -400 |
| Raw admission guard | -300 |
| Ordinary conntrack lookup and protocol processing | -200 |
| Destination NAT | -100 |
| Filter | 0 |
| Source NAT | 100 |
| Conntrack confirmation | `INT_MAX` |

The constants are in [`enum nf_ip_hook_priorities`, lines 30–47](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/include/uapi/linux/netfilter_ipv4.h?h=Ubuntu-6.8.0-117.117#n30). The actual IPv4 conntrack hooks register prerouting processing at `NF_IP_PRI_CONNTRACK` and postrouting/input confirmation at `NF_IP_PRI_CONNTRACK_CONFIRM`: [`ipv4_conntrack_ops`, lines 235–259](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nf_conntrack_proto.c?h=Ubuntu-6.8.0-117.117#n235). Hook insertion orders priorities numerically: [`nf_hook_entries_grow`, lines 104–173](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/core.c?h=Ubuntu-6.8.0-117.117#n104).

Use a `type filter hook prerouting priority -300` guard, evaluated on **every** protected packet. Its allow decision requires the installed current attachment and the appropriate pre-NAT tuple. A failed attachment must issue `drop`, before any `ct state established` acceptance. `nf_hook_slow` returns immediately on `NF_DROP`, so later hooks do not process that packet. An early accept continues to later hooks; it does not bypass the existing forward policy. [`nf_hook_slow`, lines 619–649](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/core.c?h=Ubuntu-6.8.0-117.117#n619); nftables 1.1.3 archive, `doc/statements.txt`, “VERDICT STATEMENT”.

A forward-hook drop is too late for the stronger state claim. Conntrack resolves the tuple and invokes its protocol handler before setting `IPS_SEEN_REPLY` for a valid reply. UDP processing refreshes timeouts/accounting and can set `IPS_ASSURED` after previously seeing a reply and passing its stream-time test. A first forged reply can set `SEEN_REPLY` without immediately setting `ASSURED`. [`nf_conntrack_in`, lines 1968–2045, and `__nf_ct_refresh_acct`, lines 2054–2074](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nf_conntrack_core.c?h=Ubuntu-6.8.0-117.117#n1968); [`nf_conntrack_udp_packet`, lines 83–128](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nf_conntrack_proto_udp.c?h=Ubuntu-6.8.0-117.117#n83).

Thus, on the selected ordinary path, a pre-conntrack drop prevents **this packet** from creating or refreshing a connection. It also prevents accounting, reply-seen/assured changes, and ordinary NAT for that packet. Complete table dumps can still differ across elapsed time. Timeout countdown, garbage collection, replication, management operations, and concurrent legitimate traffic remain separate transitions. Compare selected tuple/ID/status/accounting and qualified timeout behavior in isolated observation intervals. Existing NAT bindings also apply to established traffic, so checking only NAT-rule traversal or only new connections is insufficient. [`nf_nat_inet_fn`, lines 910–980](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nf_nat_core.c?h=Ubuntu-6.8.0-117.117#n910).

## Interface identity and exported rules

`meta iif` reads the input device's integer `ifindex`; `meta iifname` reads its current name. Missing devices yield zero or an empty name. These come from the hook's input-device pointer, not an Ethernet field. [`nft_meta_store_ifindex`, `nft_meta_store_ifname`, and `nft_meta_get_eval_ifname`, lines 202–244](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nft_meta.c?h=Ubuntu-6.8.0-117.117#n202); [`nft_in`, lines 65–68](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/include/net/netfilter/nf_tables.h?h=Ubuntu-6.8.0-117.117#n65).

Valid allocated indices are positive and at most `INT_MAX`, unique within the owning network namespace while allocated. Deletion releases the index; a later device can reuse it. Rename preserves the index. A namespace move can select a different index. The model needs namespace and device lifetimes alongside an index. Those lifetime labels are collector/controller evidence, not extra packet fields. [`dev_index_reserve`, lines 9728–9761](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/core/dev.c?h=Ubuntu-6.8.0-117.117#n9728), [`unlist_netdevice`, lines 407–414](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/core/dev.c?h=Ubuntu-6.8.0-117.117#n407), [`dev_change_name`, lines 1256–1320](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/core/dev.c?h=Ubuntu-6.8.0-117.117#n1256), and [`__dev_change_net_namespace`, lines 11250–11355](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/core/dev.c?h=Ubuntu-6.8.0-117.117#n11250).

The nftables 1.1.3 manual explains that `iif "foo"` resolves to an index and survives rename. An `iifname "foo"` rule can match a replacement device. More subtly, **JSON export can print the RHS of `meta iif` as a name string**, even when the input rule used an integer. Its datatype printer resolves index to name; JSON falls back to that printer. The `iif` expression key still denotes an index comparison. Resolve that exported string against a contemporaneous same-namespace link dump and stable device lifetime. The expression still compares an index. Nftables 1.1.3 archive: `doc/primary-expression.txt`, lines 16–37; `src/meta.c`, lines 112–158; `src/json.c`, `datatype_json`, lines 978–1007, and `meta_expr_json`, lines 595–599.

Ordinary conntrack tuples contain protocol, addresses, and transport selectors; neither the source MAC nor input interface is part of that tuple. Namespace and zone participate separately in lookup. Same tuple plus same zone in the same gateway namespace can therefore select the same connection from another input interface. [`struct nf_conntrack_tuple`, lines 37–75](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/include/net/netfilter/nf_conntrack_tuple.h?h=Ubuntu-6.8.0-117.117#n37); [`hash_conntrack_raw`, lines 212–227](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nf_conntrack_core.c?h=Ubuntu-6.8.0-117.117#n212).

## EAP attachment is a separate trusted association

RFC 3748 requires lower-layer per-packet authentication, integrity, and replay protection bound to EAP-derived keys to establish that later data belongs to the authenticated party. Its one-byte EAP identifier matches requests and responses, not global session ownership. A controller's local round, interface-lifetime binding, and separate authentication/data-link mapping cannot be inferred from IP/UDP headers or a copied source MAC. [RFC 3748, sections 3.4 and 4](https://www.rfc-editor.org/rfc/rfc3748.html#section-3.4).

Authorization can combine authenticated EAP information with configured non-EAP context; the outer EAP Identity remains unauthenticated. This milestone makes that context explicit rather than claiming cryptographic packet provenance. [RFC 9190, section 5.6](https://www.rfc-editor.org/rfc/rfc9190.html#section-5.6). Hostapd 2.12's wired driver has no station-authorization callback in `wpa_driver_wired_ops`; its logical authorization export alone establishes no physical data-port barrier. Source: hostapd 2.12 archive, `src/drivers/driver_wired.c`, final operations table; `src/ap/ieee802_1x.c`, `ieee802_1x_set_authorized`, lines 112–125.

An isolated gateway input port distinguishes the new adversary even if all packet bytes match. Multiple stations sharing one unprotected port remain indistinguishable to this guard. Protecting that case needs an enforced station-specific lower-layer association or cryptographic data protection; an index/MAC check alone cannot provide it. This is an inference from the metadata and EAP boundaries above.

## Observation ordering and NFLOG

On the selected receive path, generic XDP and VLAN handling can precede packet taps. `ptype_all` taps precede ingress TC and netfilter ingress; pending tap delivery is flushed before the ingress hook. Receive handlers and protocol-specific delivery follow. IPv4 `ip_rcv` then enters prerouting after its initial header checks. An incoming AF_PACKET observation can precede a later prerouting drop. That frame remains evidence of ingress, without establishing successful conntrack or forwarding. [`__netif_receive_skb_core` and `nf_ingress`, lines 5405–5600](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/core/dev.c?h=Ubuntu-6.8.0-117.117#n5405); [`ip_rcv`, lines 560–572](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/ipv4/ip_input.c?h=Ubuntu-6.8.0-117.117#n560). AF_PACKET's `sockaddr_ll` records device index and packet type separately from frame bytes: [`packet_rcv`, lines 2231–2242](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/packet/af_packet.c?h=Ubuntu-6.8.0-117.117#n2231).

A log statement at priority -300 passes the hook's actual input device to NFLOG. NFLOG exports `NFULA_IFINDEX_INDEV`; on Ethernet its optional `NFULA_HWADDR` derives the **source** MAC, and `NFULA_HWHEADER` can retain the link header. Payload copying is bounded by the configured copy range/snaplen. These exports do not require a conntrack lookup. Retain raw attributes and full selected bytes, then join to the separate AF_PACKET observation; a producer's interface label is insufficient. [`nft_log_eval`, lines 103–119](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nft_log.c?h=Ubuntu-6.8.0-117.117#n103); [`__build_packet_message`, lines 491–600 and 648–660](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nfnetlink_log.c?h=Ubuntu-6.8.0-117.117#n491); [`eth_header_parse`, lines 201–206](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/ethernet/eth.c?h=Ubuntu-6.8.0-117.117#n201).

## Required new native experiment

1. Add a separate adversary namespace and routed gateway input link. Record all namespace/link lifetimes and ifindices. The adversary receives no EAP authorization. Inject whole UDP Ethernet frames carrying the legitimate client source MAC and the exact protected request tuple. First retain a successful **header-only-policy counterexample**, with the guard absent, joined ingress, NAT/forward/output, receiver, and conntrack evidence.
2. Install the current session-to-interface attachment and pre-conntrack guard. Retain complete actual ruleset and link readbacks. Legitimate attached traffic must still reach the existing forward policy and NAT. Use raw ingress tuples. The predecessor request is `192.0.2.2:41000 → 203.0.113.2:8080`. Its reply is `198.51.100.2:9000 → 203.0.113.1:40000`.
3. Repeat adversary traffic with a fresh absent connection, then against a legitimate cached connection. Also forge the cached connection's reverse tuple from the wrong ingress. Require each pre-conntrack drop observation and absence of downstream CT/NAT/forward/output or delivery. Check for new entries, accounting increments, timeout refreshes, and `SEEN_REPLY` or `ASSURED` changes. Separate the first forged reply from a previously replied/assured case so the status checks are meaningful.
4. Invalidate the attachment on the selected EAP round's Logoff/restart or expiry. A cached connection must not restore admission. Retain the controller transition and installed-rule readback separately from the authenticator event. Consume all selected packet and observer records, with completeness/loss checks. Add regressions for wrong iif, renamed/reused devices, stale rounds, missing guards, late hooks, changed bytes, and mutated conntrack state.

This is a plan, not a claim that the new capture has already run.

## Explicit limits

Raw priority -300 follows enabled IPv4 defragmentation. Fragments may already allocate/reuse reassembly state before the guard, and noninitial fragments lack UDP ports. This whole-datagram contract does not establish fragment isolation or attribution; an earlier ingress/-450 policy and a separate reassembly argument would be needed. [`ipv4_conntrack_defrag` and its hook table, lines 62–105](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/ipv4/netfilter/nf_defrag_ipv4.c?h=Ubuntu-6.8.0-117.117#n62).

Bridges, VLANs, tunnels, redirects, and shared ports can change or aggregate the input device. NFLOG distinguishes logical and physical bridge indices when available; they must not be conflated. The new profile excludes those paths. [`br_pass_frame_up`, lines 33–63](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/bridge/br_input.c?h=Ubuntu-6.8.0-117.117#n33); [`NFLOG input-device branches`, lines 491–525](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/net/netfilter/nfnetlink_log.c?h=Ubuntu-6.8.0-117.117#n491).

Software flowtables can bypass prerouting and later hooks after an ingress hit, and hardware offload can bypass this software evidence path. Require no flowtable/offload bypass, no earlier CT action/BPF processing, no recirculated pretracked packet, and faithful complete observations during isolated intervals. Offload metadata and checksums need their own evidence; do not repair captured bytes using later packets. [Pinned kernel flowtable documentation, “Overview”](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/Documentation/networking/nf_flowtable.rst?h=Ubuntu-6.8.0-117.117#n13).

The daemon ownership join uses a conservative process-start lower bound. The pinned kernel records task creation with BOOTTIME, then exports start time through the proc reader's BOOTTIME namespace offset. See [`copy_process`, lines 2628–2629](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/kernel/fork.c?h=Ubuntu-6.8.0-117.117#n2628) and [`do_task_stat`, lines 585–587](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/fs/proc/array.c?h=Ubuntu-6.8.0-117.117#n585). The ARM64 generic definition sets `USER_HZ=100`; conversion uses exact integer division by 10,000,000 nanoseconds. See [`param.h`, line 9](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/include/asm-generic/param.h?h=Ubuntu-6.8.0-117.117#n9) and [`nsec_to_clock_t`, lines 733–736](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/kernel/time/time.c?h=Ubuntu-6.8.0-117.117#n733). Assume one kernel boot, trustworthy Linux CLOCK_MONOTONIC stamps, unchanged zero MONOTONIC/BOOTTIME namespace offsets, and daemon creation after the command's start stamp. Python's [monotonic clock implementation](https://github.com/python/cpython/blob/v3.12.3/Python/pytime.c#L1141) supports the clock selection; this does not establish binary equivalence. Under these assumptions, require `startTimeTicks >= command.startNs // 10_000_000`. Flooring permits equality within one tick; requiring `startTimeTicks * 10_000_000 >= command.startNs` can reject valid starts. BOOTTIME includes suspend time, so a MONOTONIC command-end stamp supplies no general upper bound. See [`ktime_get_boottime`, lines 88–96](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/include/linux/timekeeping.h?h=Ubuntu-6.8.0-117.117#n88). Time namespaces offset MONOTONIC and BOOTTIME independently; a shared namespace alone does not justify this comparison. See [namespace clock offsets, lines 28–35](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/kernel/time/namespace.c?h=Ubuntu-6.8.0-117.117#n28) and [proc reader offset, lines 82–86](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/include/linux/time_namespace.h?h=Ubuntu-6.8.0-117.117#n82). The retained capture does not measure those offsets, so zero offsets remain a selected-runtime assumption. This necessary bound cannot establish process identity or ancestry; retain separate PID, namespace, socket ownership, and creation-order evidence.
